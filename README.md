# Sakura 米家

通过米家 App 扫码连接账号，在插件设置中选择允许桌宠查询和控制的设备。
无需 Home Assistant，也无需手动提取设备 Token。当前版本为 `0.3.0` 个人预览版。

## 安装与登录

1. 在 Sakura 设置左侧选择 **插件**，打开右上角的更多操作菜单，选择 **从 ZIP 安装…**，安装 `Sakura-Mijia-0.3.0.sakplugin.zip`。
2. 等待依赖安装完成，启用 **米家** 并应用设置。安装时需要访问 Python 包源。
3. 打开该插件的 **插件设置 → 账号 → 扫码登录**，用米家 App 扫描软件内的二维码，并在手机上确认。
4. 登录成功后自动加载设备。在左侧选择设备，在右侧为桌宠选择 **仅查询** 或 **允许控制**，点击 **完成**，再点击设置窗口底部的 **应用**。

新设备默认不向桌宠开放。别名供桌宠查找设备，例如“床头灯”。
**读取状态** 是用户操作，不受桌宠权限限制，也不会保存尚未应用的权限修改。
状态按设备的 MIoT 定义显示中文名称、枚举和单位；没有中文定义的属性会保留原名，单项失败会显示错误码。
重新启用会尝试使用保存的凭据连接；凭据无法刷新时需要重新扫码。所有登录和设置都在 Sakura 内完成。

此版本依赖 Sakura 新增的通用 `image` 字段、`connection-status` 和 `record-table` 组件；需要 Sakura 1.3.2 或更高版本，清单通过 `min_app_version` 声明这一要求。
其他插件可以通过相同的公开设置接口使用图片、连接状态和记录列表，主程序没有米家专用登录逻辑。

当前后端固定使用中国大陆米家接口，其他地区账号未验证，也没有服务器地区切换选项。

## 本机验收环境

`dist/启动米家验收.bat` 启动同级 Sakura 仓库编译出的真实桌面程序，数据保存在本仓库的 `.acceptance` 目录。
它与日常使用的 Sakura 数据隔离。首次使用前运行下方命令准备验收环境。启动前先退出其他 Sakura 实例。

在设置左侧选择 **插件 → 米家 → 插件设置**，直接使用账号、设备和场景三个区块。
可先点击 **读取状态** 验收；对话控制还需要在验收环境配置模型、角色和对话插件。
退出程序后凭据和权限仍保留在这个验收目录；不要把 `.acceptance` 目录上传到 Git 仓库。

重新准备环境使用 `tools/prepare_acceptance.py --sakura <Sakura 源码目录>`；已有验收目录时会拒绝覆盖。

## 体验

先在插件设置中点击 **读取状态** 验证连接，再给需要的设备开放桌宠权限并应用设置，然后与 Sakura 对话：

- “查一下你能控制哪些米家设备。”
- “看看卧室灯支持什么功能。”
- “打开卧室灯，把亮度调到设备支持的 50%。”
- “看看卧室灯现在是什么状态。”

桌宠应先查询设备能力，再使用对应属性和枚举值。重名设备需要明确房间或名称。
读回目标状态时才会返回 `confirmed: true`；网关或云端接收指令不等于设备已经执行完成。
超时可能意味着结果未知，应先查询状态，不要盲目重发动作。

手动场景在 **场景** 区块单独勾选授权。授权场景将允许执行米家中配置的全部动作，
包括未单独开放的设备；修改米家场景内容会改变其执行效果。
场景列表加载失败不影响设备查询，但场景执行不可用。

## 工具

| 工具 | 功能 |
|---|---|
| `mijia_status` | 查询连接状态 |
| `mijia_list_devices` | 搜索已开放设备 |
| `mijia_get_capabilities` | 查询属性、范围、枚举及动作参数 |
| `mijia_get_state` | 读取设备属性 |
| `mijia_set_property` | 设置一项属性并尝试读回 |
| `mijia_run_action` | 执行设备动作 |
| `mijia_list_scenes` | 列出获准的手动场景 |
| `mijia_run_scene` | 执行获准场景 |

设备权限在执行端检查。查询工具不能修改权限，未授权设备无法通过猜测 ID 操作。
音箱的通用文字控制指令可间接操控其他设备，初版不开放此类动作。
不支持实时设备事件推送、摄像头视频、创建自动化、局域网离线控制或设备配网。
各设备能力取决于米家云与设备提供的 MIoT 描述，并非米家 App 的所有功能都可调用。

## 凭据与数据

数据保存在 Sakura 分配给本插件的 `connection` 私有数据目录，不写入插件安装目录。
Windows 使用当前系统用户的 DPAPI 加密账号凭据；其他系统使用仅当前用户可读写的文件，未做系统钥匙串集成。
设备授权和别名保存在独立 JSON 文件中；账号切换会清除旧设备权限。

登录二维码仅在内存保留。凭据、二维码、设备 IP、MAC 和底层设备 Token 不传给桌宠。
已授权设备的名称、能力、状态和操作结果会作为工具结果提供给当前对话模型。

**退出登录** 会删除本机凭据和设备授权，不会撤销已经发出的设备指令，也不等于在小米账号侧注销所有会话。
**取消登录** 会隔离迟到的扫码结果，不能在取消后重新保存凭据。

## 开发与验证

使用 Sakura 的 bundled Python 3.12。以下命令在本仓库运行，`<Sakura>` 替换为 Sakura 源码目录：

```powershell
& '<Sakura>\runtime\Scripts\uv.exe' pip install --python '<Sakura>\runtime\python.exe' --target .deps -r requirements.lock
& '<Sakura>\runtime\python.exe' tools/test.py
& '<Sakura>\runtime\python.exe' tools/build.py
& '<Sakura>\runtime\python.exe' tools/verify_host.py --sakura '<Sakura>'
```

安装包根目录包含 `plugin.yaml`，不包含测试凭据、缓存或开发依赖目录。
依赖安装到 Sakura 的插件专属 dependency root，普通启动不下载或升级包。
自动测试使用隔离账号与设备夹具，不连接真实家庭。
`verify_host.py` 使用临时用户根验证 ZIP 安装、真实插件子进程、工具注册与停用回收。
